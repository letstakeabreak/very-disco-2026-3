## 화면에서 달라진 것

1. **DEEP PRESS 영문 워드마크.** [눈누 PRO SLIM](https://noonnu.cc/font_page/1699)에서 출발해 [제작사](https://fonts.cafe24.com/)가 현재 배포하는 **Cafe24 PRO SLIM Max v2.0** 원본 WOFF2를 사용한다. 한글·영문을 지원하는 글꼴의 영문 형태를 골랐으며 영문 전용 서체라고 주장하지 않는다. 세로로 긴 글자와 황동/아이보리, 위·아래 선으로 프레스의 인상을 잡았다. 일반 HUD는 기존 에스코어드림, 서사 제목은 리디바탕을 유지한다. 외부 폰트 CDN 없이 번들하고 원본 PDF·OFL 전문을 첫 화면에 연결했다. [다운로드/파일 해시](font.json)
2. **이해할 수 있는 도입.** 침수된 실험실에서 도현이 부품 세 개를 건졌다. 큰 운반함을 잃어 회수 캡슐에는1L 케이스만 들어간다. 코어는 전원, 렌즈는 관측 장치, 카세트는 연구 기록이다. 내부의 가치를 지키며 외피/완충틀의 부피를 줄이는 것이 프레스의 역할이다. 세 장면을 사용자가 넘기고 되돌릴 수 있다. 시작 화면의 주 행동은 교신 연결, 보조 행동은 바로 회수다. [전체 서사 기준](story.md)
3. **기존 인물과 이어지는 일러스트4종.** 연구원 윤서의 걱정/안도, 회수 기사 도현의 설명/회수 확인 자세를 기존 남녀 원본에서 ImageGen으로 생성했다. 실제 게임의2D 대화창에 연결했다. 배경 없는 RGBA 원본을 보존하고 같은 크기 WebP로 인코딩해 합계1,264,810bytes를 배포한다. [원본·프롬프트·생성 이력](../../../../assets/source/characters/korean-salvagers-story-v1/README.md)
4. **게임 상태를 따르는 마무리.** 마지막 압축을 끝냈어도 보관/폐기 전에는 이야기가 끼어들지 않는다. 코어가 회수 완료를 알린 뒤 결과표 앞에 귀환 교신이 나온다. 카세트 회수, 손상된 카세트, 다른 부품만 회수, 빈 케이스에 맞춰 대사/표정을 선택한다. 담지 않은 기록을 회수했다고 말하지 않는다. 결과→재시작은 바로 플레이한다.

플레이 HUD에는 현재 부품의 용도가 남고 첫 조작 안내를 도현의 말로 이어 준다. 정지 메뉴에서 도입을 다시 읽어도 압력·선택·공간을 초기화하지 않는다. 대화 중 배경은 inert이며 다시 플레이할 때 키보드 초점도 조작부로 돌려준다. 자동 넘김, 강제 타자 연출, 새로운 타이머·판정·음성은 없다. 도입의 장면 번호는 렌더러 재시도 중에도 보존한다. 단, 아래에 적은 GPU 재로딩 안정성 문제는 남아 있다.

## 검증

- `npm run check`: 고정23파일, 타입,21모듈 경계,16파일103테스트, build. `git diff --check` 통과. 기존 JS500kB 권고 경고는 유지한다.
- [이야기 브라우저 검사](report.json): 390×844,320×568,768×1024,1440×900,844×390에서 도입3장면 각각 검사. 워드마크 로드/잘림,48px 버튼, 본문·장면 크기, 이전/다음/건너뛰기, 배경 비활성화, 실제 게임 시작을 확인한다.
- [기존 전체 플레이 재검증](gameplay/report.json): 실제 회전→압축→보관→정산, 정상 카세트/빈 케이스 엔딩, 압력 경고/파손, 정지·재시작·렌더러 복구. 주입 snapshot은 UI 플레이 증거로 사용하지 않는다.
- 이야기 검사는 실제 카세트를 안전선 위까지 압축해 손상 엔딩을 확인하고, 부품만 회수한 엔딩과 마지막 세 번째 물건 압축/폐기 후 자동 완료도 확인한다. 정지 중 도입 재열기 뒤 기존 압력/선택/공간, 키보드 초점을 검사한다.
- [패키지의 상대 경로 로드](package-report.json): 로컬 `/package/`에서 22개 파일이 모두 HTTP 200으로 빌드와 바이트까지 일치하는지 확인하고, 브라우저에서 글꼴·인물·주변 배경과 렌더러 로드를 검사한다. 실제 업로드/배포는 아니다. 기존 주변 배경의 CSS 변수 URL이 번들 CSS 폴더를 기준으로 해석되어 `assets/assets/`로 요청되는 문제를 발견해 앱 기준 절대 URL로 해석하도록 고쳤다.
- 생성 원본은 게임 캡처와 분리한다. 실제 iPhone·터치·safe-area·FPS는 미검증이다. 최종 검사는 PR #14/15/16/17이 포함된 A/B/C M1 통합 기준이다.

**남은 복구 문제:** 초기 B v1 기준에서 GPU context를 강제로 잃게 한 뒤 이야기 중 복구하는 검사에서 GLB 재로딩이 간헐적으로 `loadedAssets:0 / renderState:loading`에 머물렀다. [당시 진단](retry-timeout.json)을 보존했다. 수동 재현과 한 차례 전체 실행에서는 같은 장면과 renderer ready를 확인했지만 반복 안정성은 통과로 볼 수 없다. 검사 대기는 브라우저 안의 긴 Promise 대신 외부에서 동기 상태를 읽는 방식으로 바꿨으며, 변경 후에도 같은 재로딩 대기를 관찰했다. 일반 이야기/엔딩 검사는 이 인위적인 GPU 오류 주입과 분리한다. 렌더러 복구 안정성과 실기기 GPU 검증은 남은 항목이며, 요청한 이야기 흐름이 정상 동작했다는 증거로 이를 대체하지 않는다.
