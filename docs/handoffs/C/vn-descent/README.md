# 비주얼 노벨 도입 · 하강 영상 · 부가 설명 정리

2026-09-25. iOS 시뮬레이터 플레이 후 요청: 도입을 아바타 카드가 아니라 캐릭터가 직접 말하는 미연시/쯔꾸르 방식으로, 메인 화면은 영상으로 이어지게, 전체를 게슈탈트 원리로 점검, `·`와 부가 설명은 최대한 덜어내기. 이어서 HUD는 테마를 유지한 채 꼭 필요한 정보만 담아 작게, 아래 버튼도 줄이기. 그다음 폰트를 도입 대사 폰트로 맞추고, 도입과 본 게임의 핵심 연결 채우기. 출발 main `ce55d4c`(v2).

## 흐름

시작하기 → 도입 대사 9줄 → 하강 영상 6초 → 실제 첫 조작 화면 → (정산) → 엔딩 대사 2~3줄 → 결과

- **도입 대사.** 전체 화면 배경 위에 서 있는 화자 한 명, 이름표, 대사창이 있어요. 글자가 한 자씩 나오고, 아무 곳이나 누르면 나머지가 한 번에 나온 뒤 다음 줄로 넘어가요. 오른쪽 위에는 건너뛰기가 있어요. 처음 두 줄은 창밖 바다 위의 내레이션이고, 그다음 작업실로 카메라가 물러나요. 윤서는 왼쪽, 도현은 오른쪽에 서요. 화자가 바뀔 때만 등장 효과가 나오고, 같은 인물이 표정만 바꿀 때는 그림만 바뀌어요.
- **하강 영상** `public/assets/video/descent.mp4` (720×1080, H.264, 6초, 소리 없음, 749,032바이트). 창문 근접 → 조명이 켜지며 작업대로 물러남 → 어두워졌다가 실제 첫 프레임. 라운드는 영상 아래에서 이미 시작되고, 영상이 끝나면 영상이 사라지면서 HUD가 나타나요. 누르거나 Esc로 건너뛸 수 있어요. 재생 실패, 3초 안에 시작하지 않음, 탭 숨김, 동작 줄이기 설정일 때는 바로 게임으로 넘어가요. 생성 스크립트와 원본 프레임은 [assets/source/video](../../../../assets/source/video/README.md)에 있어요.
- **엔딩.** 기존과 같은 조건(무사한 카세트, 손상된 카세트, 부품만, 빈 케이스)에 맞춰 대사를 고르고, 담지 않은 기록을 회수했다고 말하지 않아요. 도입과 같은 대화 무대를 써요.
- **HUD.** 점수와 남은 공간은 높이 44px 띠 한 줄에 있어요. 물건 카드는 두 줄이에요. 한 줄은 이름(⇄)과 압력 %, 다른 한 줄은 사실 칩(부피, 가치, 내구도, 안 들어감)이에요. 압력 막대는 카드 아래 2px 선이에요. 단계 표시와 압력 라벨 줄은 뺐어요.
- **본 게임과의 연결: 작업대 대사창.** 도입이 끝나도 두 사람은 계속 말해요. 버튼 바로 위에 도입 대사창을 두 줄 크기로 줄인 창이 있어요. 모양, 이름표, 한 글자씩 나오는 방식이 도입과 같아요. 줄 수를 고정해서 대사가 바뀌어도 장면이 흔들리지 않아요. 우선순위는 삐걱 경고, 첫 물건 튜토리얼, 최근 반응 순이에요.
  - 물건이 프레스에 오르면 윤서가 그 물건이 왜 중요한지 말해요(장비를 다시 켤 코어, 바닷속을 들여다보던 렌즈, 연구 기록).
  - 돌려서 버티는 정도가 드러나면 도현이 얼마나 세게 눌러도 되는지 말해요.
  - 누르다 삐걱거리면 도현이 손을 떼라고 해요.
  - 담기, 버리기, 부서짐, 공간 초과에 반응해요. 카세트일 때는 윤서가 기록 이야기로 반응해요.
  - 튜토리얼 세 단계도 도현의 말이에요. 허용치 칩과 삐걱 칩은 대사와 겹쳐서 뺐어요.
- **폰트 하나로.** 도입 대사의 리디바탕을 HUD, 버튼, 결과까지 전부 써요. 로고만 Cafe24 PRO SLIM Max예요. 쓰지 않게 된 에스코어드림 파일 2개와 이용 조건 이미지(약 1.5MB)는 빌드와 글꼴 출처에서 뺐어요. 리디바탕은 굵기가 하나라서 굵은 글씨 대신 크기와 황동색으로 강조해요. 작은 글자는 11–15px로 키웠어요.
- **조작부.** 버튼이 8개에서 3개로 줄었어요(꾹 눌러 압축, 담기, 버리기). 물건 셋을 고르던 트레이 대신, 담거나 버린 뒤 0.7초가 지나면 다음 물건이 자동으로 올라와요. 아직 누르지 않은 물건은 카드의 이름(⇄)을 눌러 바꿀 수 있어서, 순서를 고르는 선택권은 그대로예요. '마치기'는 정지 메뉴의 '여기서 마치기'와 실패 창으로 옮겼어요. 마지막 물건을 담거나 버리면 전처럼 자동으로 끝나요.
- **타이틀 로고 (v3.1).** DEEP PRESS 워드마크를 굵은 슬랩 세리프 Alfa Slab One(OFL 1.1)으로 바꾸고, 두 줄로 쌓아 가운데 정렬했어요. UI의 리디바탕과 같은 세리프 계열이고, 주조한 쇠판에 찍힌 글자 느낌이 프레스와 맞아요. 로고 카드 문구와 버튼도 가운데 정렬했어요. 예전 Cafe24 PRO SLIM Max 파일과 이용 조건은 빌드와 글꼴 출처에서 뺐어요.
- **정지 메뉴 '처음으로' (v3.1).** 진행 중인 라운드를 버리고 타이틀로 돌아가요. 다시 시작하면 새 라운드예요.
- 정지 메뉴의 '이야기 다시 보기'는 도입을 다시 보여 주고, 끝나면 이어서 플레이해요(영상 없음). 결과 화면의 '다시 하기'는 바로 플레이해요.

- **대사 윤문.** 모든 대사를 입말로 다시 썼어요. 쉼표로 끊는 문어투("기록, 담았어요.")를 없애고, 무전으로 주고받는 말투로 맞췄어요. 대사와 UI 문구에 쉼표가 하나도 없어요.

## 덜어낸 것

| 화면 | 뺀 것 | 남긴 것 |
|---|---|---|
| 시작 | `심해 회수반 · 마지막 작업`, 설명 2줄, '바로 회수 시작' | 로고, "남길 것을 골라 주세요.", 시작하기, 글꼴 출처 |
| 이야기 | 채널 표시, 역할, 쪽수, 제목, 부품 목록 카드, 이전 버튼 | 이름표, 대사, 건너뛰기 |
| HUD | 점수·공간 카드 2개, 단계 표시, 압력 라벨 줄, 부품 용도 문장, `도현 · ` 접두, "돌려 보면…" 넛지, 허용치 문장 | 점수·공간 한 줄, 이름(⇄)과 압력 %, 사실 칩 `0.76L 가치 260 내구도 100%` |
| 조작부 | 물건 고르기 버튼 3개, 마치기 | 두 줄 대사창, 꾹 눌러 압축, 담기, 버리기 |
| 결과 | `DEEP PRESS` 머리글, 소감 문장, `N개 담음 · …` 요약, `1L당 N점` | 큰 점수, 물건별 3열 목록, 최고 기록 한 줄 |
| 실패 | 요약 줄, 설명 2문장 | 제목, 한 문장, 버튼 3개 |
| 정지 | 머리글, 설명 2줄 | 제목, 계속하기, 여기서 마치기, 이야기 다시 보기 |

화면에 보이는 `·`는 모두 없앴어요. 스크린리더용 숨김 상태 문구에만 남아 있어요.

| 전경-배경 | iPhone Safari(402×714)에서 상태 카드가 압력 게이지를 덮었어요. 렌더러가 2:3 무대를 세로 가운데 두는데, 맞춤 로직은 높이 700 미만에서만 돌았어요. 결과 카드 뒤에는 HUD가 비쳐 보였어요. | 카드를 4줄 이하로 줄였어요. 가운데 둔 무대에서 게이지가 카드에 가려질 때만 작업 구역(14–88%)을 HUD와 조작부 사이에 맞춰요. 이야기, 영상, 엔딩, 결과에서는 HUD를 숨겨 한 장면만 전경이 되게 했어요. 대화 배경은 어둡게, 인물에는 그림자를 줬어요. |
| 근접 | `·`로 사실을 이어 붙여 한 덩어리로 읽혔어요. | 칩 사이 14px 간격을 라벨과 값 사이 간격보다 크게 뒀어요. 결과는 이름·부피·가치 3열 격자예요. |
| 유사 | 황동색이 주요 행동과 장식에 섞여 있었어요. 도입은 명조, 플레이는 고딕이라 다른 게임처럼 보였어요. | 황동색은 주요 행동과 핵심 수치(압축 버튼, 압력 %, 점수, 이름표, 넘김 표시)에만 써요. 폰트는 리디바탕 하나예요. 작업대 대사창은 도입 대사창과 같은 모양이라 같은 사람들의 목소리로 읽혀요. |
| 공통 영역 | 이야기 카드가 그림, 메타, 본문, 목록, 버튼을 한 상자에 담았어요. | 대사창과 이름표를 한 발화 영역으로 묶었어요. 상태 카드는 현재 물건, 트레이는 고를 물건 셋이에요. |
| 연속 | 도입이 끝나면 게임 화면이 갑자기 나타났고, 캐릭터도 사라졌어요. | 내레이션의 창문 → 영상 첫 장면의 같은 창문 → 작업대 → 실제 첫 프레임 → HUD 서서히 나타남 → 도현의 첫 안내. 도입의 마지막 말("그럼 작업대로 가요")이 플레이 첫 말로 이어져요. |
| 간결성·초점 | 화면마다 보조 버튼과 설명이 경쟁했어요. 플레이 화면에 버튼이 8개였어요. | 화면마다 주 행동 하나(시작하기, 대사 넘김, 꾹 눌러 압축, 버리고 계속하기, 다시 하기). 플레이 화면 버튼은 3개와 정지 버튼이고, 버리기는 테두리 없는 조용한 버튼이에요. |

## 검증

- `npm run check`: 고정 23파일, 타입, 21모듈 경계, 16파일 104테스트, 빌드. 빌드 약 18.5MB/20MB.
- [check.mjs](check.mjs): headless Chrome에서 402×714, 393×760, 375×600, 1280×800을 돌렸어요. 시작 → 대사 타이핑/완성/넘김 → 건너뛰기 → 영상 재생(readyState 4) → HUD 표시 → 실제 마우스 압축 → 담기 → 다음 물건 자동으로 올라옴(광학 렌즈) → 이름을 눌러 바꾸기(데이터 카세트) → 정지 → 여기서 마치기 → 엔딩 → 결과. 페이지 오류 0.
- iOS 시뮬레이터(iPhone 17 Pro, Safari, 바이트 범위 지원 `vite preview`): 대사 넘김, 영상 자동 재생과 건너뛰기, 게이지가 보이는 첫 화면, 길게 눌러 압축, 담기, 다음 물건에서 윤서의 설명, 돌렸을 때 도현의 허용치 대사, 엔딩, 결과를 확인했어요. 실기기와 FPS는 확인하지 않았어요.
- Safari는 MP4를 재생할 때 바이트 범위 요청(206)을 요구해서, 범위 요청을 지원하는 `vite preview`로 확인했어요. 범위 요청이 없는 서버에서는 폴백으로 바로 게임으로 넘어가야 해요.
- 예전 [story-onboarding/check.mjs](../story-onboarding/check.mjs)는 이전 카드 DOM을 기준으로 해서 이번 변경으로 쓸 수 없게 됐어요. 기록으로만 남겨요.
