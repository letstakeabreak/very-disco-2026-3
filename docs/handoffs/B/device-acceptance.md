# 남은 실제 iPhone 검증

현재 기록은 **미검증**이다. 2026-09-24 연결 목록의 실제 iPhone은 unavailable이었고, 렌더러 검증에 사용할 수 있는 기기가 없었다. Mac Safari·Chromium의 모바일 viewport·시뮬레이터를 실제 iPhone 통과로 기록하지 않는다.

## B 렌더러 점검

1. `role/b-render`의 검사할 commit SHA를 기록한다. `npm ci`, `npm run check` 후 `npm run dev -- --host 0.0.0.0`으로 개발 서버를 연다. 같은 신뢰할 수 있는 로컬 네트워크의 실제 iPhone Safari에서 `http://<개발 Mac의 LAN 주소>:5173/docs/handoffs/B/preview.html`을 연다. 공개 터널이나 배포는 필요하지 않다.
2. 모델명, iOS 버전, Safari 버전, 세로/가로, 화면 CSS 크기와 DPR을 기록한다. 이 페이지 상단에 **RENDER STUDY / NOT GAMEPLAY**가 보여야 한다. 네 모델과 새 계기판이 로드되는지 확인한다.
3. 세 회수품을 각각 검사·압착·파손 상태로 전환한다. 압력 0/50/100%에 계기판 바늘이 왼쪽/위/오른쪽을 가리키는지, 렌즈 파손 조각·금속/복합재 변형·누름판 접촉·케이스 3칸 안착을 캡처한다. 화면 회전 뒤 검은 화면이나 잘림이 없는지 확인한다.
4. 상단 FPS/P95는 **최근 600 프레임** 값이다. 이를 3분 전체 통계로 옮겨 적지 않는다. 연속 프레임 전체 기록과 기기 실측이 없는 동안 PRD의 3분 기준은 미검증으로 유지한다. 데스크톱 `soak-check.mjs`의 결과를 기기 결과로 재사용하지 않는다.

## 통합 후보에서 완료할 검증

A/C의 실제 게임이 합쳐진 후보 commit에서 3분 연속 플레이로 검사 → 압착 → 손 떼기 → 정착 → 보관 → 실패/정산 → 재시작을 수행한다. 입력 취소·앱 전환·복귀·다중 터치를 함께 확인한다. 목표는 60fps, 전체 프레임 간격의 P95 ≤33.3ms, 강제 새로고침·검은 화면·입력 고착 0회다. fixture의 수동 상태 선택은 이 전 과정을 대신하지 않는다.

기록에는 commit, 실제 기기/OS/브라우저, 시험 시작·종료 시각, 전체 측정 시간·표본 수·FPS/P95, 오류 및 재현 방법, 실제 캡처, 검사자를 포함한다. 결과가 없으면 빈 숫자를 0으로 채우거나 `verified`로 올리지 않는다. 기기가 연결되면 이 문서를 계획이 아닌 실제 측정 보고서로 보완한다.
