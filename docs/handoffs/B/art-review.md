# B — 아트 목표 5개와 실제 WebGL 비교

이 문서는 아트 충실도 검토다. [비교 갤러리](art-review/index.html)와 [기계 판독 촬영 기록](art-review/capture-report.json)을 함께 읽는다. 모든 ImageGen 원본은 목표 이미지이며 실행 화면이 아니다. 갤러리의 `ACTUAL WEBGL`은 실제 GLB를 렌더한 브라우저 캡처다. 로딩 검사의 PASS가 시각 항목의 일치·완성 판정을 뜻하지 않는다.

개발 서버에서 여는 주소: `http://localhost:5173/docs/handoffs/B/art-review/index.html`. 독립 뷰어는 `capture.html?target=01`부터 `05`까지다. 생성 그림을 실제 캡처로 바꾸거나 목표에 맞게 결과 이미지를 후처리하지 않는다.

## 증거의 종류

| 목표 | 실제 실행 경로 | 대응 캡처 크기 |
|---|---|---|
| 01 작업대 | 공개 `createRenderer`, 카세트 inspecting, yaw 0.45rad | 원본과 같은 1024×1536 + 390×844 / 320×568 |
| 02 압력 | 공개 `createRenderer`, 같은 카세트·yaw, pressure 0.6 / integrity 1 | 원본과 같은 1024×1536 + 390×844 / 320×568 |
| 03 카세트 | 별도 Three.js 정적 에셋 뷰어, 최종 runtime GLB/PBR | 원본과 같은 1254×1254 |
| 04 프레스 | 별도 Three.js 정적 에셋 뷰어, 최종 runtime GLB/PBR | 원본과 같은 1254×1254 |
| 05 회수 성공 | 공개 `createRenderer`, complete fixture, 케이스에 ID 3개 | 원본과 같은 1024×1536 + 390×844 / 320×568 |

390/320은 **DPR 1 desktop Chromium의 CSS viewport**다. 실제 iPhone의 픽셀 밀도·열·메모리·터치 또는 C의 HUD/버튼/안전 영역을 검증한 것이 아니다. 01/02/05는 같은 생산용 렌더러를 사용하지만 A의 명령·판정을 실행하지 않는 fixture다. 특히 05는 저장된 물건의 압축/손상 상태가 없는 공유 계약에 따라 렌더러의 문서화된 cosmetic fallback을 사용한다. 실제 회수 성공이나 점수 결과로 해석하지 않는다.

03/04는 Blender 이미지가 아니라 실제 Three.js WebGL이다. 게임과 같은 GLB geometry, embedded color/MR/normal maps를 직접 로드한다. 별도 중성 회색 배경·바닥 그림자와 전면 왼쪽 ¾ 검사 카메라를 쓴다. 게임의 변형 셰이더를 적용하지 않는 원위치 에셋 검사다. 프레스는 production `createGauge`와 `pressure-dial.webp`를 함께 사용하되 압력 0으로 고정한다. GLB의 원래 정적 바늘만 따로 보여 주는 결과가 아니다. 카메라 방향은 카세트 `(-2,1.6,4)`, 프레스 `(-1.5,1.3,4)`를 정규화하고 실제 bounds를 화면 여백에 맞춘다. 이 근접 검사와 모바일 게임 장면을 같은 증거로 취급하지 않는다.

## 판정 기준과 현재 상태

7개 항목은 실루엣·상대 크기, 카메라 구도, 재질 구별, 환경광·호박색 포인트, 접촉·그림자, 변형 설득력, 작은 화면 가독성이다. 항목의 한정된 시각 조건을 만족하면 통과, 목표와 의미 있는 차이가 남으면 미달, 해당 캡처가 그 조건을 검사하지 않으면 미검증이다. 목표 하나의 일부 요소가 맞아도 전체 일치로 올리지 않는다. 개별 판정과 이유는 갤러리에 기록한다.

**2026-09-24 22:23 KST 촬영 시작, 11장 검증 통과.** canonical 대응 5장과 390/320 가독성 6장을 확보했다. 모든 화면이 ready였고 공개 렌더러는 GLB 4개를 로드했다. 브라우저 오류 0건, PNG 크기 일치, 촬영 전후 소스 SHA 일치를 확인했다. 최신 `PCFShadowMap` 수정까지 포함한 캡처다. **5개 목표에 대응하는 실행 증거는 마련됐지만, 아트 충실도는 부분 대응이며 전체 합격이 아니다.**

이 표의 통과는 제한된 육안 판정이다. 재질 통과는 밝은 외피·어두운 금속·호박색 중심부를 구별할 수 있다는 뜻이며 포토리얼 품질이나 원본의 미세 표면 재현을 보증하지 않는다. 03/04의 카메라 통과도 전면 왼쪽 ¾ 방향과 전체 구조 확인에 한정한다. 두 독립 뷰어는 원본과 픽셀 단위의 투영 일치, 게임 카메라 또는 모바일 가독성을 검증하지 않았다.

주요 관찰은 다음과 같다.

- **01/02/05 — 구도와 크기:** 장비 전체와 큰 하단 박스를 보여 선택 물건이 작다. 390/320에서 물건의 존재는 보이지만 접힘·손상 같은 상태를 안정적으로 읽기 어렵다. 01의 물건과 받침 접촉 위치도 목표만큼 명료하지 않다. 이는 시각 판정이며 물리적 부유를 계산해 입증한 것은 아니다.
- **02 — 압력과 변형:** 01 대비 램 하강·물건 높이 감소·게이지 바늘 변화는 보인다. 그러나 내려온 램에 물건이 가려지고 목표의 재질별 접힘을 설득력 있게 읽기 어렵다. `integrity 1`인 이 fixture는 렌즈 파손 셰이더의 증거가 아니다.
- **03/04 — 원위치 에셋:** 주요 부품과 실루엣은 대응한다. 카세트 중심부는 목표보다 불투명한 금색에 가깝고, 프레스의 따뜻한 금속 반사와 미세한 마모 표면도 단순하다. 별도 조명으로 본 근접 에셋 확인을 게임 장면 전체의 합격으로 올리지 않는다.
- **05 — 보관:** 세 물건은 모두 화면 안에 있으나 목표보다 작고, 슬롯 방향에 맞춰 들어가는 대신 케이스 앞쪽에 가로로 놓인다. 빈 홈이 뒤에 남아 슬롯 적합성과 상태 식별이 약하다. 저장 상태의 변형 이력은 공유 snapshot에 없어 검증할 수 없다.

알려진 비교 쟁점: 목표 01/02/05는 장비 상부 일부가 화면 밖으로 나가는 가까운 작업 구도다. 현재 생산용 렌더러는 장비 전체와 높은 하단 박스를 보여 주므로 선택 물건과 보관물이 작다. 비교 뷰어에서 생산용 카메라를 바꾸어 차이를 숨기지 않는다. 같은 출력 크기와 같은 2:3 비율은 카메라·상대 크기의 일치를 보증하지 않는다.

추가 개선을 한다면 작업 영역의 화면 비중을 먼저 조정하고 배경판·트레이·보관 슬롯 투영도 함께 맞춰야 한다. 그 뒤 같은 11장으로 재검사해야 한다. 별도 에셋 근접 사진만 확대해서 모바일 미달 항목을 통과로 바꾸면 안 된다. 실제 iPhone에서 조작·손상 인지·장시간 성능을 확인하는 일은 이 아트 검토 밖의 남은 검증이다.

공개 렌더러 캡처는 DPR 1에서 `visibleTriangles=81,024`, `triangles=239,048`, `drawCalls=27`을 보고했다. `visibleTriangles`는 현재 보이는 고유 mesh geometry 합계이고 `triangles`는 shadow/transmission을 포함한 여러 패스의 렌더 합계다. 둘을 동일한 폴리곤 예산으로 비교하지 않는다. 이 촬영에서는 장시간 FPS 또는 실기기 성능을 측정하지 않았다. 독립 뷰어의 통계는 에셋만 세므로 전체 장면의 수치와 별개다.

## 재현 및 출처

```sh
node docs/handoffs/B/art-review/check.mjs
```

두 번째 명령은 별도의 `agent-browser@0.38.1` Chromium 세션을 열고 4개 GLB ready, 브라우저 오류, 출력 PNG 크기, 촬영 시작/종료 source SHA를 검사한다. canonical 5장과 모바일 비율 6장을 저장하고 자신의 세션을 닫는다. 원본 5장·런타임 GLB·생산용 renderer·검사 뷰어의 SHA와 검사 HEAD는 `capture-report.json`에 남는다. 파일이 촬영 중 바뀌면 실패 처리한다.

세 번째 명령은 WebGL 뷰어를 열지 않고 정적 갤러리의 5개 비교·35개 판정·16개 이미지와 보기 전환, 좁은 화면 레이아웃을 검사한다. 결과는 [gallery-check.json](art-review/gallery-check.json)에 남는다.

이 추가 작업의 수정 범위는 `docs/handoffs/B/art-review/**`, 이 문서뿐이다. 공유 계약·의존성·A/C 모듈·생산용 렌더러·원본/런타임 에셋을 변경하지 않는다.
