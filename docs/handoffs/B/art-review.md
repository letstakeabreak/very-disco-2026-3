# B — 아트 목표 5개와 실제 WebGL 비교

이 문서는 아트 충실도 검토다. [비교 갤러리](art-review/index.html)와 [기계 판독 촬영 기록](art-review/capture-report.json)을 함께 읽는다. 모든 ImageGen 원본은 목표 이미지이며 실행 화면이 아니다. 갤러리의 `ACTUAL WEBGL`은 실제 GLB를 렌더한 브라우저 캡처다. 로딩 검사의 PASS가 시각 항목의 일치·완성 판정을 뜻하지 않는다.

개발 서버에서 여는 주소: `http://localhost:5173/docs/handoffs/B/art-review/index.html`. 독립 뷰어는 `capture.html?target=01`부터 `05`까지다. 생성 그림을 실제 캡처로 바꾸거나 목표에 맞게 결과 이미지를 후처리하지 않는다.

## 증거의 종류

| 목표 | 실제 실행 경로 | 대응 캡처 크기 |
|---|---|---|
| 01 작업대 | 공개 `createRenderer`, 카세트 inspecting, yaw 0.45rad | 원본과 같은 1024×1536 + 390×844 / 320×568 |
| 02 압력 | 공개 `createRenderer`, 같은 카세트·yaw, pressure 0.6 / integrity 1 | 원본과 같은 1024×1536 + 390×844 / 320×568 |
| 03 카세트 | 별도 Three.js 정적 에셋 뷰어, 최종 runtime GLB/PBR | 원본과 같은 1254×1254 |
| 04 프레스 | 별도 Three.js 정적 에셋 뷰어, 최종 runtime GLB/PBR | 원본과 같은 1254×1254 |
| 05 회수 성공 | 공개 `createRenderer`, complete fixture, 케이스에 ID 3개 | 원본과 같은 1024×1536 + 390×844 / 320×568 |

390/320은 **DPR 1 desktop Chromium의 CSS viewport**다. 실제 iPhone의 픽셀 밀도·열·메모리·터치 또는 C의 HUD/버튼/안전 영역을 검증한 것이 아니다. 01/02/05는 같은 생산용 렌더러를 사용하지만 A의 명령·판정을 실행하지 않는 fixture다. 특히 05는 저장된 물건의 압축/손상 상태가 없는 공유 계약에 따라 렌더러의 문서화된 cosmetic fallback을 사용한다. 실제 회수 성공이나 점수 결과로 해석하지 않는다.

03/04는 Blender 이미지가 아니라 실제 Three.js WebGL이다. 게임과 같은 GLB geometry, embedded color/MR/normal maps를 직접 로드한다. 별도 중성 회색 배경·바닥 그림자와 전면 왼쪽 ¾ 검사 카메라를 쓴다. 원본 GLB/PBR 파일은 보존하고, production과 같은 런타임 balanced 환경의 좁은 따뜻한 반사 카드·벽 반사색 ×.35·낮춘 보조광 및 프레스 재질 `roughness ×0.72` 보정값을 별도 검사 카메라에서도 사용한다. 같은 재질을 프레임·램이 공유해도 한 번만 곱한다.

게임의 변형 셰이더를 적용하지 않는 원위치 에셋 검사다. 프레스는 production `createGauge`와 `pressure-dial.webp`를 함께 사용하되 압력 0으로 고정한다. GLB의 원래 정적 바늘만 따로 보여 주는 결과가 아니다. 카메라 방향은 카세트 `(-2,1.6,4)`, 프레스 `(-1.5,1.3,4)`를 정규화하고 실제 bounds를 화면 여백에 맞춘다. 이 근접 검사와 모바일 게임 장면을 같은 증거로 취급하지 않는다.

## 판정 기준과 현재 상태

7개 항목은 실루엣·상대 크기, 카메라 구도, 재질 구별, 환경광·호박색 포인트, 접촉·그림자, 변형 설득력, 작은 화면 가독성이다. 항목의 한정된 시각 조건을 만족하면 통과, 목표와 의미 있는 차이가 남으면 미달, 해당 캡처가 그 조건을 검사하지 않으면 미검증이다. 목표 하나의 일부 요소가 맞아도 전체 일치로 올리지 않는다. 개별 판정과 이유는 갤러리에 기록한다.

**2026-09-24 23:34 KST 촬영 시작, 11장 검증 통과.** canonical 대응 5장과 390/320 가독성 6장을 모두 다시 촬영했다. 01/03/04/05 canonical과 01/05의 320px, 02의 390px를 직접 열어 검토했다. 모든 화면이 ready였고 공개 렌더러는 GLB 4개를 로드했다. 브라우저 오류 0건, PNG 크기 일치, 촬영 전후 소스 SHA 일치를 확인했다. 작업대 아래 프레스 하단 매립, 가까워진 카메라, 선택 물건 1.1배, 홈 방향에 맞춘 보관물, 새 램 기준점과 `bedShadow.receiveShadow=true`, 검사 위치 90mm 후퇴, balanced 반사 보정까지 포함했다. **실행 증거와 일부 시각 요소는 개선됐지만 아트 충실도는 부분 대응이며 전체 합격이 아니다.**

|---|---|---|---|---|---|
| 실루엣·상대 크기 | 미달 | 미달 | 통과 | 통과 | 미달 |
| 카메라 구도 | 미달 | 미달 | 통과 | 통과 | 미달 |
| 재질 구별 | 통과 | 통과 | 통과 | 통과 | 통과 |
| 환경광·호박색 포인트 | 통과 | 통과 | 미달 | 미달 | 통과 |
| 접촉·그림자 | 통과 | 통과 | 통과 | 통과 | 미달 |
| 변형 설득력 | 미검증 | 미달 | 미검증 | 미검증 | 미검증 |

이 표의 통과는 제한된 육안 판정이다. 재질 통과는 밝은 외피·어두운 금속·호박색 중심부를 구별할 수 있다는 뜻이며 포토리얼 품질이나 원본의 미세 표면 재현을 보증하지 않는다. 03/04의 카메라 통과도 전면 왼쪽 ¾ 방향과 전체 구조 확인에 한정한다. 두 독립 뷰어는 원본과 픽셀 단위의 투영 일치, 게임 카메라 또는 모바일 가독성을 검증하지 않았다.

주요 관찰은 다음과 같다.

- **01/02/05 — 구도와 크기:** 높은 하단 박스 대부분이 작업대 아래로 숨었고 카메라와 선택 물건 확대가 반영됐다. 이전의 작은 선택 물건 문제는 완화됐다. 다만 상단 볼트까지 장비 전체가 보이며 검사 전 램을 90mm 후퇴시켜 카세트 위 여유가 넓어졌다. 독립 geometry 측정에서는 bounds 간격 25.1→115.1mm였다. 목표의 상단을 자른 작업 영역 구도·기계 비율과 같은 상태는 아니다.
- **01/02 — 접촉과 압력:** 받침이 물건·램의 그림자를 받아 접촉부가 분명해졌다. 01 접촉·그림자는 이번 캡처의 시각적 연결에 한정해 통과로 변경했다. 정확한 물리 충돌이나 모든 각도의 접촉을 검증했다는 뜻은 아니다. 02에서 램 하강·높이 감소·게이지 변화가 보이지만, 램에 물건이 가려지고 목표의 보호판 접힘·파편 같은 재질별 변화는 부족하다.
- **390/320 — 가독성:** 01의 흰 외피와 금색 중심부, 01→02의 램 하강과 높이 변화는 이전보다 잘 구분된다. 체결부·외피 접힘 등 세부는 여전히 작다. 이 fixture들은 `integrity 1`이므로 실제 파손 상태를 보지도 않고 손상 가독성이 통과했다고 판정할 수 없다. 05의 물건 3개는 보이지만 종류·압축·손상 상태의 안정적인 식별에는 미달한다.
- **03/04 — 원위치 에셋:** balanced 환경에서 카세트 구조와 프레스 램의 좁은 세로 반사·따뜻한 가장자리가 드러난다. 카세트 원통은 여전히 목표보다 불투명한 금색이고, 프레스 가장자리에 작업등 색이 생겼지만 미세 마모·깊이의 차이가 남고 어두운 면의 세부가 부족하다. 생산용과 같은 조명·재질 보정값이어도 다른 카메라·중성 배경에서 본 근접 에셋을 게임 장면 전체의 합격으로 올리지 않는다.
- **05 — 보관:** 세 물건의 중심과 긴 축이 각각 홈을 따라 배치되어 앞쪽 가로줄과 뒤쪽 빈 홈 문제는 개선됐다. 배경의 케이스 자체는 목표보다 작고 오른쪽 홈·세 번째 물건 일부는 화면 끝에 잘린다. 렌즈 원판은 위로 누워 비스듬하게 보인다. 실제 케이스 벽·깊이에 따른 가림과 접촉까지 증명한 것은 아니므로 접촉·그림자는 미달을 유지했다. 새로 연 complete fixture에는 저장 압축/손상 이력이 없어 cosmetic fallback을 사용한다.

알려진 비교 쟁점: 목표 01/02/05는 장비 상부 일부가 화면 밖으로 나가는 가까운 작업 구도다. 현재 생산용 렌더러는 하단을 매립하고 가까워졌지만 상단은 여전히 모두 보여 준다. 케이스 배경의 크기·오른쪽 잘림과 회수물 자체의 모양도 목표와 다르다. 비교 뷰어에서 생산용 카메라를 바꾸어 차이를 숨기지 않았다. 같은 출력 크기와 같은 2:3 비율은 카메라·상대 크기의 일치를 보증하지 않는다.

남은 개선은 압착 진입의 즉각 이동, 원통의 내부 형상과 투명 깊이, 금속 표면과 작은 화면 손상 인지다. [램 조사](retraction-study/README.md)는 상부 자산 교차 한계를, [카세트 단면 조사](cassette-structure-study/README.md)는 원본부터 내부 코어가 없음을 기록한다. 케이스를 더 크게 보이게 하려면 배경과 슬롯의 구성도 함께 조정해야 한다. 바뀐 장면은 같은 11장으로 다시 검토한다. 별도 에셋 근접 사진만 확대해서 모바일 미달 항목을 통과로 바꾸면 안 된다. 실제 iPhone에서 조작·손상 인지·장시간 성능을 확인하는 일은 이 아트 검토 밖의 남은 검증이다.

## 촬영 기준 파일과 수치

캡처 당시 HEAD는 `1fa803075f37b8a5b0bcf23da41e616771811a18`이며 커밋 이후 작업 파일을 포함한다. 재현 기준은 HEAD만이 아니라 [capture-report.json](art-review/capture-report.json)의 전체 SHA 목록이다.

| 파일 | 촬영 전후 동일 SHA-256 |
|---|---|
| `src/render/index.ts` | `c696e329cb0fec66a7d56159c1a6e9cff7114a95ce6401de35dfa80dab8cdf20` |
| `src/render/ram.ts` | `82fecf7ce8bd82276bffd0936781313a5a0982bd6c5a000a2814da529bfea65a` |
| `src/render/gauge.ts` | `32efce024fe6aa86dbb7d45fb56d57715823fd3807d2cc75283801ab420b10ca` |
| `docs/handoffs/B/art-review/inspector.ts` | `f4f69303a3d405bb084b44832fa1b45a6b040fc9eb4ad48eda50b25de1cfee40` |
| `public/assets/textures/pressure-dial.webp` | `4a65d7022666d3ee344a5f45058ca409bd84775922783e644111ebd2ae4b6ea6` |

공개 렌더러 01/02/05의 9장은 모두 DPR 1에서 `visibleTriangles=81,024`, `triangles=239,048`, `drawCalls=27`을 보고했다. `visibleTriangles`는 visible flag가 켜진 mesh geometry 합계로 작업대 클리핑 뒤에 숨은 삼각형도 포함한다. `triangles`는 shadow/transmission을 포함한 여러 패스의 렌더 합계다. 둘을 동일한 폴리곤 예산으로 비교하지 않는다. 이 촬영에서는 장시간 FPS 또는 실기기 성능을 측정하지 않았다. 독립 카세트 뷰어는 GLB 15,000삼각형·3 draw calls, 프레스 뷰어는 GLB 42,998삼각형·9 draw calls를 보고했다. 독립 뷰어의 triangle 값은 직접 센 GLB 원본 합계이며 게이지·그림자 등을 포함한 전체 GPU 패스 합계가 아니다.

## 재현 및 출처

```sh
node docs/handoffs/B/art-review/check.mjs
node docs/handoffs/B/art-review/capture.mjs
node docs/handoffs/B/art-review/gallery-check.mjs
```

두 번째 명령은 별도의 `agent-browser@0.38.1` Chromium 세션을 열고 4개 GLB ready, 브라우저 오류, 출력 PNG 크기, 촬영 시작/종료 source SHA를 검사한다. canonical 5장과 모바일 비율 6장을 저장하고 자신의 세션을 닫는다. 원본 5장·런타임 GLB·생산용 renderer·검사 뷰어의 SHA와 검사 HEAD는 `capture-report.json`에 남는다. 파일이 촬영 중 바뀌면 실패 처리한다.

세 번째 명령은 WebGL 뷰어를 열지 않고 정적 갤러리의 5개 비교·35개 판정·16개 이미지와 보기 전환, 좁은 화면 레이아웃을 검사한다. 결과는 [gallery-check.json](art-review/gallery-check.json)에 남는다.

이번 B 보완은 생산용 램/환경 반사와 이 문서·뷰어·검증을 함께 갱신했다. 공유 계약·의존성·A/C 모듈·원본/런타임 GLB/PBR은 변경하지 않았다. 개별 미달 판정은 유지한다.
