# 카세트 손상 가독성과 투명도 회귀

2026-09-25. 직전 내부 축 구현 `27fc24446bb13e1aceb29d1b1b9cb3a4c770f3bb`에서 시작했다. 파손이 심해도 유리 외형이 남아 있던 문제를 고쳤다. 기존 ImageGen/Meshy7 모델의 유리 표면에 authored 균열·빠진 조각을 표현한다. 새 이미지·모델 생성, 유료 호출, 외부 에셋은 없다.

## 원인과 변경

1. `index.ts`가 모든 PhysicalMaterial의 투명도를 렌즈용 `.72*(1-damage*.85)`로 덮어써 카세트의 `.94` 광학 설정도 잃고 있었다. 새 회귀 테스트에서 정상 카세트의 실제 재질 값 `.72`를 관측해 먼저 실패시켰고, 렌즈에만 기존 갱신을 적용한 뒤 통과했다. 카세트는 자체 균열 셰이더로 국소 투과를 처리한다.
2. `deformation.ts`에서 원통의 X/각도 좌표에 충격점을 고정했다. 손상에 따라 방사형 균열·주변 균열과 거친 모서리가 드러나며, 심한 손상은 원래 생성된 유리 표면 일부를 버려 실제 내부 축이 보이게 한다. 균열 주변의 거칠기·투과를 바꾸고 나머지 유리의 투명 깊이는 유지한다.
3. 모든 효과는 snapshot `integrity01`에서 읽은 damage만 따른다. 시각 임계값은 게임 실패 조건이 아니다. 부피·점수·판정을 계산하지 않는다. 프레임/유리/축의 기존 압축 동작과 고정 API·에셋4개·모델 파일은 유지했다.

유리 조각의 새 물리 모델이나 동적 파편 시뮬레이션을 구현한 것은 아니다. 기존 표면의 셰이더 절단이라 유리 두께의 새로운 옆면은 없으며, 이 한계를 포토리얼 파괴 완료로 표현하지 않는다.

## 비교 방법과 범위

[이전15장](before-report.json)과 [현재21장](after-report.json)은 실제 공개 `createRenderer`를 사용한다. 320×568·390×844에서 검사/실패 자세 각각 damage0/.5/1을 촬영하고1024×1536의 검사3장을 추가했다. 현재21장에는 보관 이력을 거친320/390폭6장도 있다. 압축량 .55, yaw .45rad, 압력 .55와 카메라는 고정한다. 무결성만 비교하는 합성 snapshot이며 실제 게임 판정·사용자 인지 테스트가 아니다.

현재 캡처에서 균열과 빠진 유리 사이의 내부 축을 확인했다. 320폭의 큰 구멍은 보이지만 미세 균열은 작다. 렌즈용 설정의 덮어쓰기를 함께 고쳤으므로 정상 유리도 이전보다 투명해졌다. 이전/현재 정상 이미지가 같아야 하는 실험으로 해석하지 않는다.

GPU `readPixels`는 같은 자세의 damage0 대비 RGB차이>3/255 픽셀과 영역을 기록한다. 이것은 색상 변화의 위치·발생을 확인하는 수치이지 손상 인식 점수가 아니다. 상태별 숫자나 테스트 PASS만으로 가독성 합격을 선언하지 않는다. 보관된 damage는 직전에 본 물건의 B 내부 시각 이력이며 저장 snapshot에 없는 값을 복원했다는 뜻도 아니다.
