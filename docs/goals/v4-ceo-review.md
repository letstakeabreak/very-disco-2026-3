# Goal v4 — CEO 리뷰 25개 전부 고치기

2026-09-26. v3.1(main `860b2ea` + PR #21)을 iPhone 18 Pro Max 시뮬레이터에서 두 판 플레이하고 받은 비판 25개를 모두 받아들인 목표다. 1판은 튜토리얼대로 해서 822점이 나왔고 카세트를 부쉈다. 2판은 규칙을 알고 해서 40초 만에 990점(이론상 최고점)이 나왔다. 대회 마감은 **2026-09-28**로 연장됐다.

## 사용자 결정

- **다시 할 이유는 '오늘의 회수'.** 날짜로 물건 조건이 바뀐다. 같은 날엔 모두 같은 수치라 실력을 비교할 수 있다. 결과에는 그날 만점 대비 등급을 보여 준다.
- **긴장감은 연출로만.** 제한시간은 넣지 않는다. 경보음, 선체 삐걱임, 물 새는 연출, 다급한 대사로 위기를 표현한다.
- **오디오를 넣는다.** PRD의 '오디오 제외'를 바꾼다. 처음엔 Web Audio 합성음이었지만, 사용자가 싸구려 같다고 해서 Freesound CC0 녹음 13개로 바꿨다(PRD 1.2.1). 캐릭터 음성(TTS)은 사용자의 사이트 가입이 필요해서 이 Goal에 넣지 않는다.

## 지켜야 할 것

- 모든 변경 뒤 `npm run check`를 통과한다. 빌드는 20MB 이하, itch.io ZIP은 루트에 `index.html`, 모든 경로는 상대 경로다.
- 규칙을 바꾸면 PRD와 계약 버전을 올리고, `docs/bootstrap.json`의 고정 해시를 같은 변경에서 갱신한다.
- 대사와 UI 문구는 쉼표 없는 입말이다. 문장을 쉼표로 끊는 번역투를 쓰지 않고, 화면에 `·`를 쓰지 않는다.
- iPhone 세로 화면이 먼저다. 402×714, 375×600, 320×568, 1280×800에서 확인한다.
- 머지는 사용자가 요청할 때만 한다.

## 완료 정의

25개 항목이 아래 수용 기준을 모두 충족하고, 각각 테스트, 측정, 캡처 중 하나 이상의 증거가 있다. 마지막으로 같은 방식(처음 하는 유저 1판, 규칙을 아는 유저 1판)으로 다시 플레이하고 결과를 기록한다. 그때 아래 두 가지가 모두 성립해야 한다.
- 1판에서 튜토리얼대로 해도 막다른 길에 빠지지 않는다.
- 2판에서 하루 만점을 받으려면 세 물건을 모두 한계 가까이 눌러야 한다.

## 단계와 항목

`[ ]`는 남은 일, `[x]`는 끝나고 증거가 있는 일이다. 괄호 안 번호는 리뷰 항목이다.

### M0. 기준 갱신

- [x] PRD 1.2.0: 오늘의 회수(날짜 시드), 압력 관성과 예고 경고, 오디오 허용, 긴장 연출, 도입 스토리와 전환 영상을 반영한다. 계약 1.2.0과 부트스트랩 해시도 갱신한다.

### M1. 게임 뼈대

- [x] **G1 적재 목록 (②, ㉑).** 판이 시작되자마자 세 물건의 부피와 가치가 한 화면에 보인다. 물건 칩을 누르면 선택되고, 압축 전에만 바꿀 수 있다. 칩은 담음, 부서짐, 두고 옴 상태를 보여 준다. 기존 ⇄ 버튼은 칩으로 대체한다. HUD의 압력 % 중복은 없앤다.
- [x] **G2 첫 선택은 플레이어가 (①).** 첫 물건을 자동으로 올리지 않는다. 튜토리얼은 먼저 계획을 가르친다("셋 다 넣으려면 전부 한계까지 눌러야 해요"). 튜토리얼대로 해도 카세트가 불가능해지는 흐름이 생기지 않는다.
- [x] **G3 오늘의 회수와 등급 (③, ⑤, ㉕).** KST 날짜로 시드를 만든다. 물건마다 부피, 가치, 안전 압력을 정해진 범위에서 바꾼다. 재질별 내구 성향(유리는 약함)은 유지한다. 같은 날짜는 같은 값(테스트), 다른 날짜는 다른 값이다. 해석기로 그날 만점을 계산한다. 결과 화면은 점수를 구성으로 풀어 보여 주고(가치와 회수 보너스, 합이 맞음), 만점 대비 퍼센트와 등급을 보여 준다.
- [x] **G4 압착 실력 (④).** 손을 떼도 유압이 잠깐 더 밀어서 압력이 약간 초과된다(관성). 삐걱 경고는 손상 직전의 예고 구간부터 시작해 점점 세진다. 날짜 생성기는 만점 경로가 세 물건을 모두 담고, 셋 다 상당히 눌러야 하도록 조건을 고른다. 셋 다 담은 최적이 둘만 담은 최적보다 확실히 높다.
- [x] **G5 도입 압축 (⑥).** 도입 대사는 6줄 이하다. 이미 본 사람은 타이틀에서 한 번 탭으로 바로 시작할 수 있다.

### M2. 이야기와 규칙 일치

- [x] **G6 지킬 수 있는 부탁 (⑦).** 윤서의 카세트 부탁은 계획하는 시점(판 시작)에 나온다. 남은 물건이 최대로 눌러도 안 들어가게 되면 캐릭터가 바로 말한다. 불가능한 물건을 부탁하는 대사는 나오지 않는다.
- [x] **G7 케이스 적재 게이지 (⑧).** 케이스가 얼마나 찼는지 담은 물건별 구간으로 보여 준다. 누르는 동안 들어갈 자리도 미리 보여 준다. 남은 물건이 하나도 안 들어가면 케이스를 닫는다. *변경:* 3D 케이스 칸은 배경 그림에 그려져 있어서, 칸을 닫아 보이게 하려면 렌더러와 스냅샷(최소 부피)을 바꿔야 한다. 대신 HUD 게이지, 칩의 '안 들어감', 도현의 대사, 자동 마감으로 해결했다. 보통의 날엔 세 물건이 모두 들어가서 칸 세 개가 규칙과 맞는다. 3D 칸 닫기는 B 추가 목표로 남긴다.
- [x] **G8 행동을 인정하는 결말 (⑨, ⑫).** 물건마다 결과(담음, 손상, 부서짐, 두고 옴)를 기록한다. 엔딩 대사는 물건별 결과로 짠다. 손실 뒤에는 웃는 포즈를 쓰지 않는다. 결과 화면은 세 물건을 모두 상태와 함께 나열한다.
- [x] **G9 공간 논리 (⑩).** 윤서는 무전 화면 틀 안에 나오고, 도현은 작업실에 서 있다. 플레이어가 누구인지("프레스실") 부른다. "그럼 작업대로 가요"처럼 장면과 어긋나는 대사를 고친다.
- [x] **G10 위기 연출 (⑪).** 플레이 중에 경보 배경음, 가끔 선체 삐걱임, 물 새는 효과, 다급한 대사가 나온다. 규칙에는 영향이 없다. 제한시간은 없다.

### M3. 손맛

- [x] **G11 사운드 (⑬).** 유압음(압력 따라 음높이), 삐걱임(경고 세기), 파손, 담기, 버리기, UI, 대사 틱, 심해 배경음을 넣는다. 정지 메뉴에 음소거가 있고 기기에 기억된다. iPhone에선 첫 탭 뒤에 소리가 켜진다. 오디오 파일은 추가하지 않는다.
- [x] **G12 파손 순간 (⑭).** 부서지면 흔들림, 번쩍임, 파편, 소리가 약 1.2초 보인 뒤 실패 선택지가 프레스를 가리지 않는 아래쪽에 나온다. 손상으로 가치가 떨어지면 그 차이를 강조해 보여 준다.
- [x] **G13 대사 순서 (⑮).** 반응 대사는 다 찍힌 뒤 최소 1.5초 보인다. 다음 물건은 반응을 다 읽은 뒤에 올라온다. 삐걱 경고가 끝나도 앞 대사를 다시 타이핑하지 않는다.
- [x] **G14 튜토리얼 약속 (⑯).** 돌리면 첫 물건이 얼마나 버티는지 튜토리얼 안에서 말해 준다.
- [x] **G15 재도전 (⑰).** 튜토리얼은 기기에서 한 번만 나온다. 다시 하기는 바로 조작으로 들어간다.

### M4. 첫인상

## 진행 기록

- **M0, G3, G4 (2026-09-26):** PRD와 계약 1.2.0, 부트스트랩 해시 23개 일치. 오늘의 회수 30일치가 세 조건을 모두 만족함(`tests/core/content.test.ts`). 하루 생성 시간은 중앙값 5ms, 최대 16ms. 유압 관성과 예고 구간은 `tests/core/game.test.ts`로 확인.
- **G1, G2, G3, G5, G6, G14, G15 (2026-09-26):** headless 흐름 `v4-flow`를 402×714, 320×568, 1280×800에서 실행했다. 스크립트는 새 저장소로 시작하고, 삐걱 0.15초 뒤에 떼는 사람 속도를 흉내 낸다.
  - 도입은 6줄이다.
  - 첫 물건은 자동으로 올라오지 않고, 칩 세 개가 부피와 가치를 보여 준다.
  - 돌리면 도현이 버티는 정도를 말하고("약해 보여요. 압축하기를 누르다 삐걱대면 떼요."), 약한 렌즈와 카세트는 손상 없이 담긴다.
  - 결과는 1,282점, 오늘 만점 1,325점 중 96%로 A등급이다. 줄 합계(342+520+420)가 점수와 같다.
  - 다시 하기에선 튜토리얼 없이 윤서의 카세트 부탁으로 시작한다.
  - 남은 물건이 못 들어가면 이름을 말하고, 전부 못 들어가면 케이스를 닫는다(`tests/app/story.test.ts`).
- **G7, G8, G9, G13, G21 (2026-09-26):**
  - 케이스 게이지는 담은 물건과 누르는 중인 물건을 구간으로 보여 준다(`caseFill` 테스트).
  - 엔딩은 물건별로 말하고, 부순 기록은 "결국 부서졌네요"라고 하며, 셋 다 담았을 때만 도현이 웃는다(`tests/app/story.test.ts`).
  - 윤서는 청록 무전 화면 틀 안에, 도현은 작업실에 서 있다(캡처).
  - 읽은 대사는 다시 타이핑하지 않고, 선체 대사는 지금 대사를 다 읽은 뒤에만 나온다.
  - 놀람과 슬픔 연출이 있다. 새 포즈 그림은 ImageGen이 필요해서 의존 항목으로 남긴다.
- **G10, G11, G12, G19 (2026-09-26):**
  - 합성 사운드를 headless Chrome에서 분석기로 쟀다(RMS). 첫 탭 전엔 꺼져 있고(`data-audio=off`), 진짜 클릭 뒤 running이다.
    - 배경음 0.061, 누르는 중 0.092, 삐걱 0.111, 뗀 뒤 0.057, 음소거 0.000.
    - 정지 메뉴의 음소거는 기기에 기억된다. 선체 울음과 먼 경보도 같은 엔진이다.
  - 파손 때는 1.2초 동안 흔들림, 붉은 번쩍임, 파손음이 먼저 나온다. 그 뒤 선택지가 아래에 떠서 부서진 렌즈와 파편이 보인다(캡처).
  - 가치가 깎이면 "가치 −88"처럼 잠깐 보여 준다. 남은 물건이 없으면 '여기서 마치기'를 숨긴다.
  - 실제 기기에서 소리를 들어 보는 건 사용자 확인으로 남는다.
- **G16, G17, G18, G20 (2026-09-26):**
  - `index.html`이 첫 프레임부터 어두운 배경과 로딩 링을 보여 준다.
  - 3D 모델과 글꼴을 3초 늦게 주는 서버에서 1.2초 시점엔 로딩 링(`overlay-loading`, renderState loading)만 보였고, 약 5초 뒤 준비되면서 타이틀이 떴다. 로고 글꼴은 `font-display: block`이라 기본 글꼴로 먼저 뜨지 않는다.
  - 세로 402×714, 440×956, 375×600에서 압력계 윗단이 로고 아래, 케이스 아랫단이 카드 위에 있다(측정). 데스크톱에서는 로고와 카드가 좌우 여백에 있다. 문구는 "눌러서 줄이고 1리터에 담아요."다.
